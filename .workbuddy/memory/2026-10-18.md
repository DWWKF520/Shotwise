踩到并解决的坑（高价值，后续同类迁移必看）：
1. **int64 精度**：mtime_ns revision（~1.8e18）经 map[string]any → float64 往返会掉 100ns（ULP=256ns），
   触发 stale_confirmation。仓库必须直接存 `json.RawMessage`。
2. **读后置序**：必须先读内容后 stat，否则迁移期写回改变 mtime 使基线 revision 失效。
3. **锁不可重入**：promote 内部的锁定读必须走未锁 `readScriptMigrated`，否则自死锁。
4. **空切片序列化**：Go nil slice → `null`，Python 空 tuple → `[]`；所有返回点归一为 `[]T{}`。
5. **equality 不能用 `==`**：any 上 `==` 遇 map/slice 会 panic；用 reflect.DeepEqual + 归一化。
6. **通用换行**：os.ReadFile 保 CRLF，Python read_text 是 universal newlines；char_count 会差 190。
7. **截断按码点**：utf8.RuneCountInString 对 Python str 切片。
8. **错误信封**：Python 全局异常处理是 `{"detail": "<翻译串>"}`（字符串非对象）→ apperr.NewText。
9. **asset.go 竞态**（存量）：ResolveKey/RekeyEquivalent 依赖 map 迭代序，改为确定性规则
   （优先已 NFC 规范化的 key，退化按字典序）修复 TestBucketResolveKeyCoversNFDDuplicates 偶发失败。
10. **沙盒限制**：`go test -race` 在本环境对所有包（含存量 pricing）报 0xc0000139
    （STATUS_ENTRYPOINT_NOT_FOUND），非代码问题；验证用普通模式即可。
