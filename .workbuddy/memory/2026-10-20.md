## SPA 静态服务（本轮落地）

- `internal/app/spa.go`：NoRoute 兜底 + history 路由 fallback，语义对齐 Python
  server/app.py 末尾的 dist 挂载：
  - 挂载条件是 `dist/index.html` 为真实文件（检查文件而非目录），不完整仅 warning，
    API 不受影响；
  - fallback 仅 GET/HEAD；写请求误入页面路径仍 JSON 404；
  - `/app/` 深链带扩展名（`/app/projects/x/source/chapter1.txt`）无条件回外壳，
    `dist/app/...` 真实文件优先防遮蔽；
  - 其余路径：真实文件原样服务（`http.ServeFile`，含条件请求）；**带扩展名的缺失
    文件 404**（缺失哈希资源回 HTML 200 只会拖成白屏）；无扩展名回外壳（wouter）；
  - 越界防护三重：NUL 拒绝 → Clean（前导 `/` 钳制 `../`）→ dist 前缀 + symlink
    落点（EvalSymlinks）校验；
  - **显式差异**：`/api/` 前缀未知路径保持 JSON 404——前端 fetch 错误处理按 JSON
    信封解析，回 text/html 200 会静默破坏报错路径。Python 侧 `/api` 未知路径实际
    落入 fallback 回外壳，Go 不跟。
- `internal/config/config.go::ResolveFrontendDist`：`SHOTWISE_FRONTEND_DIST` env 优先，
  否则从 cwd 向上回溯（≤6 层）找 `frontend/dist/index.html`，模式同 AgentProfileRoot。
- `internal/app/spa_test.go`：外壳回退 / 深链带扩展名 / 静态文件 / 缺失哈希 404 /
  写请求 / 未知 API JSON 404 / 路径穿越 / HEAD / 不完整 dist 跳过挂载 / env 覆盖。
- 顺手修 app.go 既有的 import 乱序（textgen 与 repository）。

## agent runtime 凭证接线（本轮落地）

生产凭证链：**DB 活跃 agent 凭证优先，env 兜底，按次解析**。

- `service/agent_credential.go::ResolveActiveModel`：查活跃凭证，**按 protocol 过滤**——
  Go 运行时是单一 Eino 循环只讲 chat_completions（`agent/provider.go`），含经 OpenAI
  兼容网关接入的 Claude；`anthropic_messages` 是 Claude SDK 子进程协议，Go 运行时
  不会说，跳过。model 列空回落预设默认模型；凭证不齐（缺 key/base_url）跳过；
  单用户部署不按 user 过滤，id 升序取第一条。
- `agent/runtime.go::WithModelResolver`：解析器注入位。关键观察——prepareAgent 是
  TurnLoop **每轮回调**（buildAgent → chatModel），解析器每轮一次，设置页切换凭证
  从下一轮起生效，无需重启；失败当场报错不缓存。override（测试注入）仍最高优先；
  未注入 resolver 保持原 chatModelOnce 惰性单例（dev env 部署）。
- `main.go` 装配 resolver 闭包：ResolveActiveModel 命中 → 凭证三元组；未命中 →
  env `LLM_MODEL/LLM_API_KEY/LLM_BASE_URL`。
- 测试：service 4 例（预设默认模型 / 凭证 model 优先 / anthropic 协议跳过 /
  非活跃缺 key 跳过）+ agent 3 例（按次调用 / 错误传播 / override 优先）。

**语义边界**：活跃凭证若全部是 anthropic_messages 协议 → 静默回落 env（dev 配置），
不报错——设置页显示「已激活」但 Go 运行时用不了，属已知收敛差异，后续可考虑在
agent_config 响应里带协议可用性提示。

## 踩坑

- **gofmt -l 全仓库标红是 autocrlf 假象**：`core.autocrlf=true`，工作区 CRLF、仓库存
  LF，提交时归一，CI 的 gofmt 不受影响。判真实格式差异须先 LF 归一再 `gofmt -l`。
- Write 工具写出的文件是 CRLF，与仓库工作区一致，无需特意处理。
